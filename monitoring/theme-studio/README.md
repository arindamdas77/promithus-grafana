# Dashboard themes

Grafana in this stack is **13.2.2**. Dashboards are generated by `scripts/build_dashboards.py` and file-provisioned from `monitoring/grafana/dashboards` every 10 seconds. The generator is the source of appearance. Editing the JSON by hand is overwritten the next time the generator runs.

## What Grafana can and cannot theme

Dashboard JSON can set series colors, gauge thresholds, stat colors, and table value mappings. Grafana 13.2.2 does not provide a dashboard color-picker variable, and it ignores custom page background, panel chrome, panel border, table header, and link colors. Those values are stored with the theme and shown in the theme studio preview. They are not written as unsupported dashboard properties.

The running Grafana preference (light or dark) still controls the page chrome. Light Professional is meant to be used with Grafana's light preference. The other presets are meant for the dark preference. Change that under the avatar menu, **Profile → Preferences**, or as an org admin under **Administration → Default preferences**. This studio does not call the Grafana admin API and does not read `GRAFANA_PASSWORD`.

Healthy stays green, warning stays amber or yellow, and critical stays red. Offline stays gray. No data stays a separate neutral. Apply rejects a palette that would make those statuses hard to tell apart.

## Change colors

From the repository root, with nothing else bound to port 3013:

```sh
python3 scripts/theme_server.py
```

Open `http://127.0.0.1:3013/`. The page is also linked as **Theme** on every generated dashboard.

1. Pick a preset or use the color controls. The preview updates before anything is saved.
2. **Apply Theme** writes `monitoring/theme/active.json`, keeps the prior palette in `monitoring/theme/previous.json`, and regenerates the dashboards.
3. **Reset to Default** restores Dark Professional and keeps the current palette as the previous one.
4. **Restore Previous Theme** swaps back to the palette from before the last apply, reset, or restore.
5. Refresh Grafana. Provisioning reloads the JSON about every 10 seconds.

An unsaved preview is kept in this browser under `localStorage` key `monitoring-theme-draft`. The dashboards themselves follow `active.json`, so the applied colors stay in place when you move between dashboards or refresh Grafana.

The studio listens on `127.0.0.1` unless `THEME_STUDIO_BIND` is set. Binding beyond localhost requires `THEME_STUDIO_TOKEN`. Send it as `Authorization: Bearer <token>`. The optional Compose service publishes only `127.0.0.1:3013` and still requires that token because the process inside the container binds all interfaces:

```sh
docker compose up -d --no-deps theme-studio
```

Run that from `monitoring/`. It should create `theme-studio` only. Do not run a full `docker compose up` if you need the existing Prometheus, Grafana, Loki, and Alertmanager containers left untouched.

## Dashboards

| Page | Data |
| --- | --- |
| Server Monitoring | Summary cards and the server table |
| Infrastructure Overview | Summary, server health, problems, services, and the monitoring stack |
| Server details | Capacity, disks, network, services, and process counts |
| Network Monitoring | Host traffic, errors, and drops |
| Website & SSL | Blackbox HTTP and certificate checks |
| Alerts & Logs | Firing alerts and shipped logs |
| Monitoring System Health | Prometheus, Grafana, Blackbox, Alertmanager, and Loki |
| Database Monitoring | systemd state for MySQL, MariaDB, PostgreSQL, and Redis only |
| Docker Monitoring | systemd state for `docker.service` only |
| Backup Monitoring | Explanation only. No backup metrics are scraped |

Database query stats need a database exporter. Container CPU, memory, and restarts need cAdvisor and a Prometheus job. Backup age and success need a backup exporter. Those pages say so instead of drawing an empty success chart.

## Validate

```sh
python3 scripts/build_dashboards.py
```

The generator refuses to replace the JSON if an existing Prometheus query would disappear. It also checks that panel ids are unique, panels fit the 24-column grid, and `schemaVersion` is 42.

After Grafana reloads, `scripts/health-check.sh` should list each dashboard uid as OK. Grafana logs should not contain `dashboard provisioning error`.

## Roll back

The last applied palette is in `monitoring/theme/previous.json`. Use **Restore Previous Theme**, or from the repository root:

```sh
cp monitoring/theme/previous.json monitoring/theme/active.json
python3 scripts/build_dashboards.py
```

To return to the git version of the dashboards and drop the theme files:

```sh
git checkout -- monitoring/grafana/dashboards monitoring/docker-compose.yml scripts/build_dashboards.py scripts/health-check.sh playbooks/02_grafana_provisioning.yml
rm -rf monitoring/theme monitoring/theme-studio scripts/theme_catalog.py scripts/theme_server.py
```

Refresh Grafana after the files change. No container restart is required for dashboard JSON. A restart is required only if you change `monitoring/docker-compose.yml` and want the optional `theme-studio` service itself to pick up that change.
